## Issues faced (symptom → cause → fix)
- **Casting to a Nest Mini hung on "connecting".** The speaker never answers a LAUNCH of MCO's app;
  MCO waited 15 s before falling back. → audio-only devices go straight to Google's receiver
  ([ADR 0020](../adr/0020-speakers-use-default-media-receiver.md), [research](../research/cast-devices.md#nest-mini-and-mcos-app)).
- **The progress bar didn't move, then jumped.** Progress only ticked per finished track, with 4 in
  parallel. → workers report after each step ([ADR 0006](../adr/0006-analysis-in-worker-threads.md)).
- **FX knobs slow, app freezing.** `App`/`Player` re-rendered the whole tree on every knob tick
  ([ADR 0023](../adr/0023-fx-settings-outside-react.md)). Profiling then showed ~40 fps even idle:
  ~54k DOM nodes from rendering every row ([ADR 0024](../adr/0024-virtualised-track-table.md)).
- **~12 % CPU with nothing playing.** Two AudioContexts rendering silence
  ([ADR 0025](../adr/0025-suspend-idle-audio-engines.md)).
- **LP filter "too noisy".** Resonance applied to wide-open stages (+20 dB at 20 kHz/20 Hz) and
  clipping sweeps ([ADR 0029](../adr/0029-filter-resonance-fades-in.md)).
- **Tag editor could erase tags (1.0.39).** Found while building filename suggestions: file tags were
  only read during analysis (2,501 tracks unanalysed), so the editor opened empty and Save would have
  removed existing title/artist. → background tag reading and re-read before editing
  ([ADR 0027](../adr/0027-read-file-tags-in-background.md)). The user was told not to save tags on
  unanalysed tracks in 1.0.39.
- **Writing tags safely.** ffmpeg would drop WAV cue/bext and other apps' chunks; a byte-level writer
  was built and verified on copies of real files. Verification caught two real problems before any file
  was touched: an MP3's ID3v1 block still carrying old values after clearing, and MP3 duration
  estimates shifting with tag size ([ADR 0026](../adr/0026-write-tags-byte-for-byte.md),
  [research](../research/audio-file-tags.md)).
- **Continuous play stopped while casting.** The receiver reports `paused` before `finished`; MCO
  paused its local copy short of its end ([ADR 0021](../adr/0021-advance-queue-on-device-finished.md)).
- **The Mac slept and casting hung; "Cast connected" while watching Plex.** No sleep prevention; Google
  TV only backgrounds the Cast app ([ADR 0022](../adr/0022-cast-session-lifetime.md)).
- **"Lost connection" while the TV kept playing (1.0.42).** The new silence timeout measured wall-clock
  time; a busy main process delayed both the timer and the TV's queued replies. The TV was verified to
  answer every heartbeat. → count missed heartbeats (PR #69).

## Process notes (for whoever works on this next)
- **Don't run `prettier --write` on a whole file**: the repo isn't prettier-formatted, and it rewrote
  400+ lines of `App.tsx` (reverted).
- Measuring the running BETA: launch it with `--remote-debugging-port=9333` and drive it over the
  DevTools protocol (Runtime.evaluate, Profiler, Page.captureScreenshot, WebAudio.getRealtimeData). Mute
  the `<audio>` element before playing anything; put back any setting a test changes.
- Reading the live DB from outside with a read-only `node:sqlite` connection can show stale data
  while the app writes; trust the app's own counts.
- Probing Cast devices: a separate connection that only sends `GET_STATUS`/`PING` doesn't disturb a
  running session.
- Quit the BETA before `npm run dist:beta`, relaunch after.
- Merges happened before the changelog was labelled twice → docs-only `[skip ci]` PRs (#65, #68);
  hence [ADR 0035](../adr/0035-changelog-labelled-in-the-feature-pr.md).

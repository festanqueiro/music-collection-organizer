# Session, 2026-10-12: no checkboxes, tag counts, and sections 1 and 2 of the review

On the branch `last-row-clear-of-scrollbar`, not committed or merged at the time of writing.

## Asked for
- **Track counts on tags**: each row of the Tags and Subtags views ends with how many tracks it
  would list, written like a playlist's song count ([Tags](../features/tags.md#filtering-by-tag)).
- **No checkboxes in the table**: rows are selected as in Finder
  ([ADR 0068](../adr/0068-select-rows-without-checkboxes.md)).
- **"The 2/3 always shows a wrong BPM"** in Refine BPM…: no arithmetic fault was found. The item
  was called *Two-thirds fix (× 1.5)* and multiplies by 1.5 (it fixes a tempo *found at* two
  thirds), so on 120 it shows ≈ 180, which reads as wrong under that name. Renamed **One and a half
  times (× 1.5)**, and a real **Two thirds (× ⅔)** added. This is a reading of the report, not a
  reproduced bug: to confirm with the user.
- **Are Rekordbox cue positions relative to a start time?** No: seconds from the start of the file,
  as the player's clock had them ([Hot cues](../features/hot-cues.md#with-rekordbox)).

## Section 2 of the whole-app review
All of it, with the notes at the top of
[that section](2026-10-11-whole-app-review.md#2-broken-and-a-user-would-notice). Findings while
fixing:
- **Harmonic order.** Making the claim true (most harmonic changes first) was a change of what is
  minimised, and the search for many keys needed more than a wider neighbourhood: with reversals
  and moves of up to three keys it was still one harmonic change short in 5 of 12 sets of 21 keys.
  What closed it is an exact search for the fewest changes out of key, cheap because each key has
  three harmonic neighbours ([ADR 0067](../adr/0067-harmonic-order-over-keys-not-songs.md), note).
- **Bit depth**, on files made with ffmpeg and `afconvert`: music-metadata 11.16 gives
  `lossless: false` with a correct `bitsPerSample` for AIFF-C (`sowt`, `fl32`, `BEI24`) and for a
  float WAV with a `fact` chunk; for Apple's 24-bit ALAC it gives 16, the MP4 sample entry's size
  field. The real depth is byte 17 of the 36-byte `alac` box inside the sample entry.
- **Similar tracks → Add to playlist…** did close on the click that opened it (the review had it as
  *plausible*): the new smoke check failed before the fix.
- **Queue view's progress bar**: not found in the code; left.
- A 50-minute synthetic track analyses in 150 s with essentia limited to its first 20 minutes.

## Section 1 of the review (can lose or damage data)
All twelve, with the notes at the top of
[that section](2026-10-11-whole-app-review.md#1-can-lose-or-damage-data). Two got an ADR:
[0069](../adr/0069-warn-when-open-on-another-computer.md) (a warning when the collection looks open
on another computer) and [0070](../adr/0070-interrupted-tag-save-offers-the-original-back.md) (a
tag save cut short offers the original back at the next launch, asked, never done unasked).
None of the failures were provoked in the running app: they are covered by unit tests on temporary
folders (a locked subfolder, a truncated backup, a torn file, a deferred playlist read).

## Questions left for the user
- **Two computers on one collection**: is that something to support? Today the database holds
  absolute paths and the shared config one collection folder, so it only works if both mount the
  collection at the same path. The warning added is a hint; a real answer needs a decision.
  **Answered (2026-10-12): no need** — one collection on two computers isn't wanted, so nothing
  more is built for it.
  The user did expect a collection moved to another computer to keep its analysis, cues and
  playlists: it didn't (every file came in as a new track). Now it does —
  [ADR 0071](../adr/0071-a-moved-collection-keeps-its-tracks.md).
- **A track that can't play** — **answered: skip it, with a toast.** Done, with a stop after
  three in a row (`src/state/unplayable.ts`). The question was: the queue waits (a toast says so). Should it skip to the next one
  instead — at the risk of running through the whole queue when a drive is unplugged?
- **Update Collection** doesn't say when it skipped an unreadable folder; and the move dialog's
  default button is still *Move*. Worth changing?
- **"The 2/3 BPM is wrong"** — **answered: no, it is the number shown beside the item that is
  usually off.** That number was the plain product (106.58 × 1.5 = `≈ 159.87`), while the change
  itself measures the tempo on the audio near it and sets 160. The menu now shows the measured
  number (`tracks:previewBpm`, same `multipliedBpm` as the change). Whether the tempo *set* is
  also off for some tracks is not known: to check with the user on real tracks.
- **Queue view's progress bar**: does it move for you?
- **Esc** in the table now goes back from several selected rows to one. Keep?

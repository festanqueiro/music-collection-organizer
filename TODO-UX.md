# UX improvements to consider

- `src/components/FolderTree.tsx`, `TagTree.tsx`, and `TrackTable.tsx` all hide meaningful functionality (rename/delete/recolor a tag, per-folder analyse/queue, per-track play-next/analyse/show-in-folder) exclusively behind right-click context menus with no visual affordance (no "⋮" button, no hint text, no first-run tooltip) indicating they exist. A new user is unlikely to discover tag renaming or per-folder analysis at all. Add a small "⋮" icon button next to hoverable rows as a discoverable entry point into the same menu.
- `src/components/TrackTable.tsx`: columns can be reordered by dragging headers but never hidden — anyone who doesn't care about the Format/Cloud/Status columns is stuck scrolling past them forever on every table row. Add a simple column-visibility toggle (e.g. a small "Columns" button in the toolbar row above the table, next to "Add all to queue") alongside the existing reorder/sort.
- `src/components/UndoToast.tsx`: genre/subgenre deletion shows an undo toast with a hardcoded 8-second auto-dismiss and no visual countdown (progress bar/ticking number). Users who look away for a moment lose the ability to undo a destructive delete with no warning it's about to disappear. Add a shrinking progress bar or countdown number to the toast.
- `src/components/TrackTable.tsx`: when analysis fails, the only feedback is a small red error icon in the Status column with a generic "Analysis failed" tooltip — there's no way to see *why* it failed (corrupt file, unsupported format, etc.). `analyzeTrack`/the worker currently swallow the error, so this needs an error column (or similar) persisted alongside `analysis_status`, then surfaced in the tooltip or DetailPanel.
